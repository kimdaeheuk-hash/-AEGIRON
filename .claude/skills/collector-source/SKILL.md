# collector-source

## ⚠️ 먼저 — 소킹 중이면 새 소스를 붙이지 않는다

런칭 전 소킹 규칙: *"고장 나지 않으면 코드를 안 건드린다. 새 소스·새 지표 추가 금지"*(09-19 에 붙인 코로나 축이 22시간 만에 거짓 critical).
새 소스는 소킹이 끝난 뒤이거나 캡틴이 명시했을 때만.

## 소스 하나가 지켜야 할 것

1. **실패와 '값 없음'을 구분한다.**
   - 실패 → 예외를 삼키지 말고 `log_error`, 소스 건강이 `중단` 으로 센다.
   - 값 없음(수집은 정상이나 이번엔 쓸 값이 없음) → `mark_no_data(result, key)` **그리고 사유를 로그에 남긴다.**
     실패로 세면 상시 degraded 로 경보가 울려 사람이 무시하게 되고, 성공으로 세면 죽은 소스가 산 것으로 보고된다.
2. **실패 사유를 집계한다**(`_fmt_failure_reasons`). `HTTPError 503×179` 처럼 — 조용히 버리면 왜 안 느는지 아무도 모른다.
3. **여러 조각을 더하면 `sum_if_complete()`.** 일부만 실패하면 낮은 숫자가 아니라 `None`.
   "한 도시 실패해도 나머지는 계속 수집"은 의도된 설계다 — 바꾸는 건 *판정*뿐이다.
4. **실패 시 0 을 돌려주지 않는다**(0-on-failure). `total_kw_hits: 0` 이 '보고가 끊김'으로 읽혔다.
5. **쉼표·단위·빈 문자열**을 파싱 시험에 넣는다(`"1,296"`).
6. **신뢰도 카테고리**는 `trust.SOURCE_TRUST` 에서 고른다. 새 값을 만들면 *왜 그 숫자인지* 주석에 적는다.
7. **원천의 갱신 주기를 확인한다.** 우리는 매시간 읽는데 원천이 주 단위면 '아직 안 나온 주'가 0 으로 온다.
   KDCA 는 `week_is_reported()` 가 막는다(#43). 새 주간 소스는 같은 문제가 있다고 가정하고 시험한다.
8. **소스 건강에 잡히는지 확인한다.** `📊 소스 건강: 정상 N/M` 의 M(총계)이 늘어난다 — 문서의 숫자가 아니라 로그의 숫자를 믿는다.
   `늙는중`(status ok 인데 마지막 성공이 3시간 초과)이 8/13 사고를 나흘 끌었던 사각지대를 잡는다.

## 판정 대상에 넣을지 (부정적 공간)

`negative_space.REPORTING_CHANNELS` 는 **허용목록**이다. 기준은 하나 — 기관·언론 채널이 내놓는 *보고 건수*인가.
검색 관심도·SNS 언급수·우리 파생 카운트는 아니다(사람들이 덜 검색한 것은 기관이 보고를 멈춘 것이 아니다).
넣을 때는 **누적값인지 주간값인지 확인**하고, 확인하지 않았으면 넣지 않는다(`africa_cdc_*` 가 그래서 빠져 있다).
빠진 것은 `제외 미선언 N` 으로 로그에 세어진다 — 목록은 그 줄을 근거로 늘린다.

## 끝내기 전

- 시험: 성공 / 부분 실패 / 전체 실패 / 값 없음 / 파싱 이상 — 다섯 경로.
- 배포 뒤: 소스 건강에서 이 소스가 정상으로 잡히는지 **로그로 관측**한다(`prod-observability`).

## 10-17 에 배운 세 가지 (소킹 일지 10-12·10-16·10-17)

- **`site_count` 는 사이트 수가 아니라 표본 행 수다** (`fetch_cdc_nwss`, SoQL `count(*)`). 키 이름은 기록 호환으로 두고 로그는 `표본 N건`. 평균(`avg`)은 이상치에 지배되므로 같은 창의 **최댓값**을 함께 남긴다(실패해도 평균은 살린다).
- **새 역학주간은 일부만 채워져 온다** (`kdca_anomaly.latest_week_is_partial`): 전 질병 합계가 직전 주 중앙값의 60% 미만이고 그 주가 시작된 지 3일이 안 되면 `kdca_weekly_total` 은 None(판정 안 함)이다. 기록 시각(`timestamp`)으로 나이를 잰다. 대가: 새 주 첫 사흘 안의 진짜 붕괴는 사흘 동안 못 잡는다.
- **404 가 '정상 지연'인 것은 정오(UTC) 전까지다** (`collector.wiki_404_is_lag`): 그 뒤에도 404 면 실패로 세고 문서 존재 확인(`wiki_article_status` — 리다이렉트를 따라가지 않고 상태·Location 만)을 사유에 붙인다. 24주기 연속 404 인데 로그가 매시간 `정상 지연` 이라 적었다.
