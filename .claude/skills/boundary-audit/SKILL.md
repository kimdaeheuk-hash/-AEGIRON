# boundary-audit

버그가 늘어난 게 아니라 **이제야 불을 켠 것**이다. 여섯·일곱 번 나온 결함이 전부 같은 모양이면 무작위가 아니고, 그래서 끝이 있다.

## 계열 1 — 경계에서 자격이 떨어져 나간다

값이 '경계'를 넘을 때 그 값의 *뜻*이 바뀌는데 코드는 같은 값으로 읽는다. 실제 사례(전부 프로덕션에서 났다):

| 경계 | 사고 | 고침 |
|---|---|---|
| 기간(주) | KDCA 새 주 = 아직 안 나온 0 → "보고 끊김" 100점 (09-21) | `week_is_reported()` (#43) |
| 창 재척도 | 네이버 세 축이 00:00 에 동시에 무너짐 (09-22) | `RESCALED_METRICS` (#43) |
| 조각이 빠진 합계 | LocalNews 179개 피드 전멸 → 0 → 붕괴 (09-19), 일본 IDWR (독감 90%) | `sum_if_complete` (#39) |
| 원천 주기 > 수집 주기 | 시간별로 읽는 주간 지표 | cadence 인지 (#37, #43) |
| 평균이 문턱 위 | `social_mpox` 평균 2.59 > `MIN_MEANINGFUL_AVG` 2.0 | 허용목록 (#44) |
| 날짜(자정) | 어제 행이 오늘 화면에 남음 | 내림 (#46) |
| 등급 | low→critical 에서 통보 안 나감 | `escalated` (#44) |

**감사 질문**: 이 값에는 *언제 뜻이 바뀌는가*? 새 기간 시작 · 창 이동 · 소스 부분 실패 · 단위/척도 변경 · 자정 · 배포 · 등급 변경.
각각에 대해 "그 순간의 입력을 넣으면 무엇이 나가는가"를 시험한다.

**증거가 문턱을 이길 때**: 문턱을 조이는 것으로 막히지 않으면(위 `social_mpox`) *대상이 아닌 것*을 자격 선언으로 걸러낸다.

## 계열 2 — 만들어만 두고 아무도 안 부른다

- 텔레그램은 evidence·honesty 를 안 보냈다(웹만 그렸다). → #39
- `resolve_due_predictions` 채점기가 있었는데 수동 API 뿐이라 성적표가 영원히 비었다. → #42
- `_gai_overall_evidence` 는 근거를 만들고 아무도 안 보냈다.

**감사 질문**: 이 함수의 호출자는 누구인가? 그 호출이 *스케줄러 경로*에 있는가? 그 결과가 *사람이 보는 곳*에 도착하는가?
**시험**: 호출 경로를 AST 로 고정한다(`testing` 참고).

## 계열 3 (신생) — 서로 상쇄하는 두 고장

09-22 에는 등급 통보가 안 나가는 결함이 거짓 경보를 가려줬다. **서로 상쇄하는 두 고장이 제일 조용하고 제일 위험하다.**
한쪽을 고칠 때 다른 쪽이 가리던 것이 드러나는지 본다 — 고친 직후 며칠은 알림을 *더* 세밀히 관측한다.

## 절차

1. 사고를 **입력 그대로 재현**하는 시험부터 쓴다(옛 동작이 경보였다는 것까지 고정).
2. 같은 모양이 다른 곳에 있는지 grep 으로 훑는다(#39 는 한 곳에서 시작해 세 곳을 더 찾았다).
3. 고친 자리를 *지표를 만드는 쪽*에 둔다 — 증가 쪽 엔진도 같은 사실을 보게(#43).
4. 프로덕션 **경계 시각에서** 관측한다(#43 은 09-23 00:01, #44 는 09-28 00:01 에 검증). 테스트는 경계가 아니다.
5. 못 가르는 자리는 코드 주석에 *명시*한다("발행 안 됨"과 "발행됐는데 전부 0"은 이 데이터로 구분 불가 → 판정 보류).
