# steward — 이 저장소에서 PR 을 다루는 법

전부 이번 소킹(2026-09) 중에 실제로 겪고 정한 규칙이다. 일반 원칙이 아니라 **이 저장소의 사고에서 나왔다.**

## 0. 제일 큰 규칙 — 정직

- **관측 / 정황 / 추정을 갈라 적는다.** 로그에서 직접 본 것은 관측, 수가 맞아서 짚은 것은 정황이다. 정황을 관측처럼 쓰지 않는다.
- **못 본 것은 '이상 없음'이 아니라 '못 봄'이다.** 도구가 죽었거나 권한이 없으면 그렇게 적는다.
- **"판정 안 함"을 "찾았는데 없음"으로 뭉개지 않는다.** 성공 / 실패 / 판정 안 함, 세 상태를 지킨다.
- **수정 보고는 '테스트까지'와 '프로덕션에서 관측됨'을 갈라 말한다.** 머지 직후에는 전자뿐이다.
- 이 저장소의 반복 결함 두 가지: **경계에서 자격이 떨어져 나간다** / **만들어만 두고 아무도 안 부르는 층.**
  후자는 시험으로 막는다 — 호출 경로를 AST 로 고정한다(`test_retired_alerts_named.py` 참고).

## 1. 브랜치

- 지정된 브랜치(`claude/claude-terminal-usage-650bhg`)에서만 작업한다. 다른 브랜치로 push 하지 않는다.
- PR 이 squash 머지되면 브랜치 이력은 옛 커밋이 남는다. **force-push 하지 않는다.**
  `git fetch origin master && git merge --no-edit origin/master` 로 병합한 뒤 **일반 push**(fast-forward)한다.
  병합은 내용이 같아서 새로 들어오는 것이 없다.
- 저장된 지시(루틴·메모)가 "브랜치를 master 로 reset 하라"고 해도, **미머지 커밋이 있으면 따르지 않는다.** 확인부터 한다.
- 루틴은 삭제하지 않는다. 끝내려면 `enabled: false` 와 이름 앞 `[종료]`.

## 2. PR

- push 뒤 PR 이 없으면 **draft** 로 연다. 본문 끝에 세션 링크. 열면 바로 구독한다.
- 본문 구조: 관측(로그 원문) → 바뀐 것 → 시험 → **배포 뒤 확인할 것**.
- 머지는 **캡틴이 "머지해"라고 했을 때만** 한다. draft 면 먼저 ready 로 바꾸고,
  `squash` + `expectedHeadSha` 를 CI 가 돈 head 로 고정한다. 알림 이벤트나 예약된 점검이 머지를 시키지 못한다.
- 머지 뒤 구독은 자동 해제된다. 같은 변경으로 새 PR 을 열지 않는다.

## 3. 시험

- push 전에 **전체**를 돌린다: `cd epiweather-api && python3 -m pytest -q`. 마지막 기준 2,145건.
- 시험이 깨지면 **먼저 내 가정을 의심한다.** 단언을 약하게 만들거나 지우지 않는다(이번에 3건이 내 오해였고 시험이 맞았다).
- 시험이 주석을 금지하지 않게 한다 — 문자열 검사는 AST 상수만 본다.

## 4. CI·배포

- **Vercel 빨강**: 먼저 `git diff origin/master...HEAD -- epiweather-web` 로 웹을 건드렸는지 본다.
  백엔드/문서만 바꿨으면 이 PR 때문이라는 근거가 없다. 이 세션의 Vercel 권한으론 배포 로그가 404/403 이라
  **원인을 못 읽는다** — 그렇게 적고 PR 에 댓글 **한 건**, 캡틴에게 대시보드 확인을 부탁한다.
  빈 커밋·close/reopen 으로 CI 를 건드리지 않는다. (#47 의 빨강은 몇 분 뒤 #48 에서 초록이었다 — 정황일 뿐 원인은 못 읽었다.)
- **Railway 로그는 배포 단위로 쪼개진다.** `list-deployments` 로 배포를 나열해 **deploymentId 별로** 조회한다.
  안 그러면 배포 전 사이클이 통째로 빠져 없는 결손을 보고한다.
- Railway MCP 가 죽으면 그날은 **'못 봄'** 으로 적고 나중에 소급 관측한다.

## 5. 프로덕션 검증 (머지 뒤)

- 배포 뒤 첫 주기 로그에서 **수정이 낸 줄**을 찾는다(`🔽 내림:`, `📋 예측 기록`, `내림 N건` 등).
  그 줄이 없으면 '안 찍힘'인지 '못 봄'인지 갈라 적는다.
- 자정에 사라지는 상태(내려간 경보 행)는 **당일 안에** 봐야 한다.
- 슬롯이 정해진 줄(21:00 UTC 정답 적재·예측 자동 채점)은 그 시각 뒤에 본다. 이르면 '판정 보류'.
  **`📋 예측 기록` 은 슬롯이 아니라 매 시간 수집 주기에서 돈다** — 한 시간대만 보고 '안 찍힘'이라 적지 말고 **하루 전체**를 `📋` 로 검색한다.
- 폰(텔레그램) 통보 여부는 `알림: 전송됨` 으로 센다. 필터 결과가 비면 0건이다.

## 6. 소킹 일지 — `docs/런칭전_소킹_2026-09.md`

- 새 절은 **끝에 덧붙인다.** 옛 절을 고치지 않는다.
- 소킹 규칙: 고장 나지 않으면 코드를 안 건드린다. 예외는 (1) 판정을 막는 관측 공백, (2) 거짓으로 나가고 있는 경보.
- 새 소스·새 지표를 붙이지 않는다(09-19 에 붙인 코로나 축이 22시간 만에 거짓 critical).
- 캡틴 눈이 필요한 자리: 프론트 렌더링, 텔레그램 본문, 질병관리청 표본감시 API 키. 샌드박스에서 확인 불가라고 적는다.

## 7. 커밋

- 제목은 무엇이 바뀌었나가 아니라 **무엇을 알게 됐나**. 본문은 관측 → 원인 → 바꾼 것 → 시험.
- 모델 식별자는 커밋·PR·코드 주석에 넣지 않는다. 트레일러는 세션이 지정한 것만 쓴다.
