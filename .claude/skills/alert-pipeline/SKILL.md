# alert-pipeline

```
수집 → 지표 → 후보(collect_candidate_alerts) ─┐
                부정적 공간(scan_negative_space) ─┴→ refresh_alerts → 등급·캡 → 화면 / 텔레그램
```

## 점수와 등급 (`algorithms/alerts.py`)

- `trusted_score = raw_score × trust` (신뢰도는 `trust.SOURCE_TRUST`).
- 등급(`classify_tier`): critical ≥ 90 · high ≥ 80 · medium ≥ 70 · 그 아래 low. **`CANDIDATE_FLOOR = 50` 미만은 후보도 아니다.**
- 하루 캡: `DAILY_CAPS = {"critical": 3, "high": 5}`(medium·low 는 무제한). 대시보드 상단은 `DASHBOARD_TOP_N = 5`.
- `refresh_alerts(today)` 는 후보를 `db.upsert_alert` 로 올린 뒤 캡을 적용한다. **행을 지우지 않는다** — `suppressed` 로만 가린다(감사 기록).

## 부정적 공간 감시 (`negative_space.py`)

"평소 활발하던 **보고 채널**이 조용해지면 보고 체계가 무너진 것"이라는 추론이다. 전제가 성립하는 지표만 판정한다:

- **허용목록 `REPORTING_CHANNELS`(9개)** 만 본다. 나머지는 사유별로 세어 로그에 낸다(`계절성 · 미선언 · 재척도 · 표본불안정 · 관측부족`).
- `eligibility(metric_id)` 가 (판정 가능?, 사유)를 돌려준다. 옛 제외 집합 셋은 **왜 뺐는지를 들고 있어서** 지우지 않았다.
- 문턱(`DROP_RATIO=0.5`, `MIN_MEANINGFUL_AVG=2.0`)으로는 못 막는 문제가 있었다 — `social_mpox` 의 평균 2.59 가 2.0 을 넘었다.
  **그래서 제외 목록을 늘리지 않고 자격을 선언하게 했다.** 대가: 판정 대상 ~30개 → 9개.
- 늘릴 때는 `collector-source` 의 기준(기관·언론의 보고 건수인가, 누적/주간 확인했는가)을 따른다.

## 소표본 카운트 문턱 (2026-10-04)

`social_*`(Mastodon 7일 게시자 수)는 평소 N 이던 카운트가 N+2 가 되는 것만으로 z-score 상한(=최대 이상도)에 닿는다 — 10-03 에 콜레라 3→5명이 critical 90.0, 뎅기 9→12명이 high 87.6 으로 폰까지 갔다.
경험적 표준편차는 '과거가 얼마나 평평했나'를 재지 카운트의 불확실성을 재지 않기 때문이다.

- **승격 자리에서만** `(관측값 − 과거 평균) / √max(평균, 1) ≥ 2σ` 를 본다(`signal_metrics.meets_count_significance`). **지수(GAI)는 안 건드린다**(측정값).
- `gai.compute_gai` 가 지표마다 `baseline_mean` 을 내보낸다(점수에는 영향 없음).
- 대상은 `social_*` 뿐이다 — 막는 목록이지 허용 목록이 아니다. 지표를 늘릴 땐 '평소 N 인데 작은 변화에 최대 이상도가 났다'는 관측을 먼저 확인한다.
- 통과·차단 모두 `🧮 [alerts] 소표본 유의도` 로 계산값을 로그에 남긴다 — 실제 평균이 값으로 읽힌다.

### 2σ 문턱은 부족했다 — 경보 점수 상한 (2026-10-04 관측)

배포 직후 `🧮` 줄이 실제 평균을 말했다: `social_cholera 관측값 5 · 평균 1.7306 · 2.49σ → 통과`, `social_dengue 12 · 5.0578 · 3.09σ → 통과`. 포아송으로는 유의해서 문턱이 못 막았다. 문턱을 3σ 로 올리면 이 두 건에 맞춘 숫자가 된다(콜레라만 막힌다).
그래서 **등급의 상한**을 건다: `COUNT_NOISE_ALERT_CAP = 79.0` — 단독 사회 카운트 신호는 high(80) 에 못 닿는다(무역 신호 79 상한과 같은 원칙). 경보 **점수만** 깎고 지수는 그대로이며, 깎으면 `🧢 [alerts]` 로그와 근거 한 줄이 남는다. 정책 선택이므로 되돌리려면 상수 하나다.

### 날짜 경계 · 판정 안 함 (2026-10-04)

- **전송 기록 · 이월** (2026-10-04, 캡틴 지시 9번): `alerts.notified_rank` 에 **전송이 성공한** 최고 등급만 기록한다(`db.mark_alerts_notified`). 채널이 설정돼 있으면 이 기록이 `escalated` 의 기준선이다(`baseline_rank`) — 오늘과 어제를 합친다. 같은 등급은 날이 바뀌어도 다시 안 나가고, 등급이 오르면 나간다. 완화는 기록을 낮추지 않는다. **전송이 실패하면 기록하지 않는다 → 다음 주기에 재시도**(요약 줄에 `알림: 전송 실패(미전송 N건, 다음 주기에 재시도)`). 채널이 없으면 재시도할 곳이 없어 예전처럼 '잡힌 행 = 본 것'으로 세고 기록은 비운다(거짓으로 '보냄'을 적지 않는다). 마이그레이션 시점의 옛 critical/high 행은 **보낸 것으로 간주**해 채웠다(관측이 아니라 간주 — 안 채우면 배포 직후 재전송). 행이 내려갔다 되살아나도 보낸 기록은 남는다.
- **판정 안 함**: 무역 스캔이 일부 실패했거나(품목 사용 불가 · 응답 못 받은 달) 예외가 난 주기엔 `trade_surge:` 행을 **내리지 않고** `⏸ 판정 안 함:` 줄로 센다. 후보가 없다는 건 값이 내려간 게 아니라 못 본 것이다. 신호 통로는 `_UNDETERMINED` 컨텍스트 변수(시그니처를 안 바꾸려고). 낡은 호출 기록(120초 초과)으로는 주장하지 않는다.
- **부분 스캔 캐시**: 실패가 섞인 스캔은 15분만 캐시한다(온전하면 6시간). 빈 달은 실패가 아니다(신고 지연의 정상 모양).
- **429**: UN Comtrade 가 429 를 주면 5초(Retry-After 있으면 그 값, 최대 20초)씩 두 번까지 기다려 다시 묻는다. 품목당 대기 합계 40초 상한. 달 사이 0.5초 간격. 429 외 실패는 전처럼 바로 버린다. 달별 행 수는 `rows_by_period`, 500행 상한에 닿은 달은 `[500행 상한 k달]` 로 줄에 찍힌다.

### 고위험 병원체 단건 보도 — `headline:` 계열 (2026-10-07, `pathogen_sentinel.py`)

카운트 지표로는 못 잡는 사건(예: 이르쿠츠크 항페스트 연구소 연구원 사망)을 위한 별도 경로. Google News 제목에서 페스트·탄저·두창 + 건강 맥락 단어(사망·격리·발병…)를 찾고, **서로 다른 매체 2곳 이상**이 보도해야 후보가 된다. 점수는 **medium 고정값 72**(측정 아님, `SENTINEL_MAX_SCORE` 79 미만 — 단독으로 high 불가, **폰을 안 울린다**). 근거 둘째 줄이 "측정값이 아니라 헤드라인 키워드 일치"라고 말한다. 비유·고유명사(plagued by · A Plague Tale · 밴드 Anthrax)는 `NOT_A_DISEASE` 로 거른다. 에볼라·마르부르크·니파는 일부러 뺐다(풍토 사건이 많아 경보 피로). 조회 실패는 `headline:` 행을 내리지 않고 `⏸ 판정 안 함`(무역과 같은 `_UNDETERMINED`). 로그 `📰 고위험 병원체 보도: 제목 N건 조회 → 후보 M개`. 폰 알림으로 올릴지는 **정책 결정**이라 안 했다. 이 층을 시험하는 파일 밖에서는 conftest 가 `fetch_local_feed` 를 빈 피드로 막는다(경보 후보를 모으는 모든 시험이 이 호출을 만난다).

### 판정 못 한 행의 낡음 표시와 자정 넘김 · 설명불가 키 · 이어받기 (2026-10-09)

- **낡음 표시**: `⏸ 판정 안 함` 행은 근거 맨 앞에 `⏸ 이번 주기 판정 못 함 — 아래는 MM-DD HH:MM UTC 에 마지막으로 확인한 값이며 지금 확인된 것이 아니다` 가 붙는다(`alerts.stale_marker`). **`updated_at` 은 안 건드린다**(`db.set_alert_evidence`) — 그 값이 마지막 실제 확인 시각이다. 다시 판정되면 근거가 통째로 새로 써져 사라진다. `⏸` 로그 줄에는 `(마지막 확인 … UTC)`.
- **자정 넘김**: 날이 바뀐 첫 주기에 판정 못 한 계열(`trade_surge:`·`headline:`)의 어제 행을 같은 표시와 함께 새 날 표에 만든다(`_carry_forward_undetermined`, 마지막 확인이 `CARRY_MAX_HOURS`=48 이내). 값을 새로 주장하지 않는다.
- **설명불가 키**: `unexplained:{ISO3}`(위치가 한 나라로 읽힐 때, `unexplained_key`). 같은 사건이 추출 표현만 달라져(`Irkutsk, Russia`/`러시아 시베리아`) 폰이 이틀 연속 울린 것을 막는다. 한계: 같은 나라의 다른 설명불가 사건은 한 키로 묶인다.
- **이어받기**: 어제 알린 등급이 오늘도 이어지는 행(`🔕 … (어제 이월)`)은 오늘 행에도 `notified_rank` 를 잇는다 — 안 그러면 이어지는 critical 이 이틀에 한 번 다시 울린다. 하루라도 행이 끊기면 이어짐이 끝나 새 소식이 된다.

### 계절 감시 합계 상한 (2026-10-27, 캡틴 지시 "일본 계절 상한 79로 걸어")

10-19 17:28 `공식신호 · japan_idwr_total 82.4점(관측값 67357(평소 약 40,534))` high → 폰. 관측값은 실측이지만 지수가 전년 동기와 견주지 않아 가을·겨울 독감 상승이 '평소 대비 급증'으로 읽힌다. `signal_metrics.SEASONAL_ALERT_METRICS`(지금은 `japan_idwr_total` 하나)의 **경보 점수만** `SEASONAL_ALERT_CAP`=79 로 제한, 로그 `🧢 … 계절 감시 합계`, 이유는 근거 둘째 줄. 지수(GAI)·국가 위험도·유입 주간 보고서 순위는 안 건드린다(측정값). 대가: 계절을 넘는 진짜 급증도 이 지표 혼자서는 폰을 안 울린다.

**한계 셋.** ⓪ 다음 창도 이상치(예: 1.5M)면 직전 값과는 비슷하고 오염된 평균과는 10배 미만이라 상한이 안 걸려 다시 울릴 수 있다. ① NWSS 의 10배는 관측 한 건(26.5배)에서 나온 판단 상수이고, 이 샌드박스가 `data.cdc.gov` 에 못 나가 분포를 못 봤다 — '인공물'은 가설이다. 진짜 급증이면 공식·뉴스 층이 같이 올라 종합(gai:overall)이 말한다. ② 같은 주간 값을 매시간 기록해 기준선이 자기 값으로 오염되는 문제(평소 93,658 → 108,705)는 고치지 않았다 — 모든 주간 지표의 기준선을 건드리는 변경이라 따로 다룬다.

### 무역 스캔의 '덜 찬 최신 달' (2026-10-04, 수리 목록 19번)

신고가 늦게 들어와서 최신 달일수록 신고국이 적다(프로덕션 `[행 78/71/64/57/42/8]` → 최신 달 8곳). '최신 달에 있어야 시계열에 남는' 규칙 때문에 후보 국가가 8곳으로 줄었고, 그 정도가 달마다 달라 무역 경보가 월 경계마다 있다 없다 했다.
- `fetch_public_series` 가 최신 달의 신고국 수가 **앞 달들 중앙값의 50% 미만**이면 그 달을 **통째로** 뺀다(`MATURITY_MIN_RATIO`). 앞 달 중앙값이 20곳 미만이면 판정 안 함(`MATURITY_MIN_REFERENCE`). 시계열은 최소 3개월을 남긴다. 빈 달도 같은 규칙으로 빠진다.
- 뺀 사실은 줄에 남는다: `[최신 202607 · 202608 제외(8곳<기준 64의 50%)]`. 스캔 결과에는 `latest_period` · `excluded_periods` · `effective_lag_months` · `mixed`(품목마다 최신 달이 다름), 경보 근거에는 실효 지연과 제외한 달이 들어간다.
- **대가**: 일찍 신고한 소수 국가의 가장 최근 값은 그 스캔에서 못 쓴다. `0.5`·`20` 은 관측 한 벌(78/71/64/57/42/8)에서 나온 판단 상수이고 실데이터로 검증하지 못했다(샌드박스는 UN 에 접속 불가).

## 통보 (텔레그램)

**본문 구성 (2026-10-04 검토)**: 근거는 앞 두 줄만 간다. 1줄 = `관측값 12(Mastodon 7일 게시자 수, 평소 약 5.1)`(단위는 `signal_metrics.METRIC_UNITS`, 모르는 단위는 비움 · 평소 값은 `approx_baseline` 으로 반올림, 로그엔 원값), 2줄 = `원시 이상도 93.5점 × 출처신뢰도 0.9 = 84.2점`(상한이 걸리면 `→ 경보 점수 79.0점으로 제한` 을 같은 줄에). 개입 브리핑(`summary_line`)은 **질병별 실측 파라미터가 있을 때만** 숫자를 싣고, 일반 예시 상수(`generic_tier`)면 `질병별 파라미터가 없어 시나리오를 만들지 않음` 사유만 보낸다. 브리핑 dict 본체와 명시 요청 API 는 그대로다.

- 신규 critical/high 만 보낸다. 상태: `전송됨 / 전송 실패 / 보낼 신규 경보 없음 / 채널 미설정 / 판정 안 함`.
- **에스컬레이션**(`escalated`): 처음 보는 source 는 보낸다 · low→critical 은 보낸다 · critical→critical 은 안 보낸다 ·
  critical→high 는 안 보낸다 · high→critical 은 보낸다. 낯선 등급 문자열은 0 으로 본다(모르는 값이 진짜 경보를 막으면 안 된다).
  (09-22 에 등급이 올라가도 통보가 안 나간 적이 있다 — `already_seen_today` 가 source 만 봤다.)
- `seen_rank` 는 **upsert 전에** 계산한다. 그래서 내려갔다 되살아난 행이 폰을 두 번 때리지 않는다.
- 근거 첫 두 줄이 텔레그램에 같이 간다. 데이터가 `<`·`&` 를 포함할 수 있으니(`parse_mode=HTML`) 값은 전부 이스케이프하고 우리 태그는 템플릿에서만 쓴다.

## 내림 (#46, #47)

후보에서 빠진 행은 `retired` 로 화면·등급 집계에서 내린다(행은 남는다, 되살아나면 upsert 가 다시 올린다).
등급 캡의 `suppressed`("한도에 밀림")와 **따로** 센다("판정에서 빠짐"). 로그 `🔽 내림:` 이 이름을 말한다.
⚠️ **열린 질문**: 내림은 "이번 사이클에 후보가 아니다" 하나로 결정된다. 값이 내려간 것과 *스캔이 못 낸 것*이 섞이면
수집 실패가 진짜 경보를 조용히 내릴 수 있다. 캡틴 결정 대기 중(스캔이 못 낸 경우를 '판정 안 함'으로 가르는 안).

## "왜 울렸나 / 왜 안 울렸나" 추적 순서

1. `🚨 경보 주기` 줄의 이름 목록과 근거 첫 줄 → 무엇이 몇 점이었나.
2. `🔇 부정적 공간` 줄의 `급감 N건` 이 0 인데 경보에 그 이름이 있으면 → **옛 행**이다(같은 사이클 대조가 증거).
3. `🔽 내림` → 어떤 행이 화면에서 내려갔나.
4. `📊 소스 건강` → 입력이 끊긴 게 아닌가.
5. 그래도 모르면 **'판정 못 함'** 으로 적는다.
