# prod-observability

**로그가 진실의 창이다.** 테스트가 통과한 것과 프로덕션에서 도는 것은 다르다 — 보고할 때 둘을 갈라 말한다.

## 어디서 읽나

- Railway 프로젝트 `아이기론`(`3ef2b6c7-2674-43d5-80c6-dd6be297ed04`), 서비스 `epiweather-api`(`bf7384d4-2ae6-41b6-ab28-754bcf01346d`).
  같은 계정의 `neo-oceanos` 프로젝트와 `MALAKH` 서비스는 **무관하다.**
- 샌드박스는 `railway.app` 에 curl 이 막힌다(프록시 403 — 정책이지 장애가 아니다). **Railway MCP** 로 읽는다:
  `list-deployments` → `get-logs(deploymentId=…, filter="…", startDate/endDate)`.
- `master` push 는 자동 배포된다(약 1분). `meta.commitHash` 가 머지 커밋과 같은지 본다. 새 배포는 뜨자마자 수집을 한 번 돈다.

## ★ 로그는 배포 단위로 쪼개진다 ★

배포가 있었던 날 `serviceId` 로만 조회하면 이전 배포의 사이클이 안 보여 **없는 결손을 보고하게 된다.** 반드시 **deploymentId 별로** 조회한다.

## 로그 줄 용어집 (2026-11-22 개편 뒤)

| 줄 | 뜻 |
|---|---|
| `=== 수집 시작 (극지 · 헤임달 · 발할라) ===` … `=== 수집 끝 ===` | 매시 수집 한 주기 |
| `  극지 관찰: N개 관측지 · 등급 … · 상위 …` | 극지 요약. `기상 자료 없음 k/N(판정 안 함)` 이 붙으면 일부 지점 기상 미수신 |
| `  ❌ 극지 관찰: 모든 관측지 기상 자료 없음 …` | 이 주기 극지 측정 없음(소스 건강 실패). 다음 줄 `Open-Meteo 실패 사유: HTTP 429×n …` 이 원인 — 429 는 일일 한도 |
| `  Nextstrain <빌드>: 우세계통 …` / `  ⏭ Nextstrain …` | 헤임달 계통 읽기 / 건너뜀(사유) |
| `  🧬 변이원장 <빌드>: …` | 우세 계통 전이가 기록된 주기에만 |
| `  🛡 매칭원장 <병원체>: <판정>` | 발할라 대조 판정(하루 한 행) |
| `  발할라: 백신 단일공급원 …` · `발할라 준비태세/승인제품/파이프라인: …` · `⚠ 발할라 … (N시간 전 값 사용)` | 발할라 조각들. 무거운 조각은 주기가 지났을 때만 새로 받는다 |
| `  📊 소스 건강: 정상 N/3 · 이름(상태)…` | 세 소스의 건강. 맵에 없는 옛 항목은 자동 정리 |
| `🗄 관측 저장: 극지 N(새 a·같음 b·판정 안 함 c)` | 극지 관측값 시계열 저장 결과 |
| `주간 작업: 기준 스냅샷 …` | 7일마다 기준 스냅샷 갱신 |

**알림 채널은 없다** — 텔레그램은 2026-11-22 개편에서 전부 제거했다. 운영 이상은 아래 외부 감시(GitHub Actions)가 작업 빨간불로만 알린다.

## 서버 밖 감시 (GitHub Actions)

- **Liveness**(`.github/workflows/liveness.yml`, 매시 :25·:55 — 예약은 자주 빠진다) — `/health` · `/api/status` 의
  `source_health.collector_silent_hours`(2시간 초과면 '매시 주기 멈춤 의심') · 웹 첫 화면. 문제가 있으면 작업이 빨간불(GitHub 자체 알림).
- **Ledger backup**(`ledger-backup.yml`, 매일 03:17) — 변이·대조 원장 + DB 전체(시크릿 `EPIWEATHER_API_KEY`).

## 검증 절차 (머지 뒤)

1. `list-deployments` → 새 배포 id·`commitHash` 확인.
2. 그 deploymentId 로 **수정이 낸 줄**을 `filter` 로 찾는다.
3. 찍혔으면 그 값이 정당한가를 같은 사이클의 다른 줄과 대조한다.
4. 안 찍혔으면 **'안 찍힘'인지 '못 봄'인지 갈라 적는다.** 슬롯이 아직 안 왔으면 '판정 보류 + 볼 시각'.

## 못 봤을 때

Railway MCP 가 죽으면 재시도 후 **'못 봄'** 으로 적고 무엇을 못 봤는지 나열한다. 못 본 날을 '이상 없음'으로 적지 않는다.
