# 관측 데이터 활용 계획 (2026-11-15)

캡틴 지시(2026-11-15)를 10개 항목으로 나눔.
① 쌓인 데이터를 어느 페이지에 붙일지
② 수집 데이터를 어떻게 가동해서 아이기론에 흡수할지
③ 대시보드 0~8단계에 어떻게 줄지
④ 데이터로 판매할 수 있는 것
⑤ 발병 지도를 지구본으로
⑥ 발병국이 어떻게 대처하는지
⑦ 확산을 어떻게 막을지
⑧ 각 나라 질병청에 알릴 수 있게
⑨ 우리나라
⑩ 극지

이 문서는 각 항목의 판단과 순서를 적음. ✅ = 이미 함 · ▶ = 다음에 할 것 · ❓ = 캡틴 결정 필요.

## 0. 지금 상태 (사실)

**측정하고 있는 것**
- 운영 서버가 매시간 다음을 실제로 받고 있음:
  - 나라별 발생 보도(AI 구조화 추출)
  - 극지 8곳 기온·해빙일수
  - 18개국 기후
  - 의료물자 수입(UN Comtrade)
  - 재난(GDACS)
  - CDC 여행 경보
  - WOAH 동물 질병
  - 유전체 계통(Nextstrain)
  - SNS 게시량
  - 보고 공백
  - 설명 불가 신호

**쌓이는 것과 안 쌓이는 것**
- 쌓임(DB에 시계열로 남음): 경보, 추출 신호, 예측, 지표 이력.
- 안 쌓임: 극지·기후·무역·재난·여행경보.
  - 이 층들은 요청할 때 계산해서 돌려주고 끝남.
  - 그래서 "지난달 대비"를 보여 줄 수 없음.
  - 판매 가능한 이력 데이터도 되지 않음.
  - **이게 가장 큰 구멍임.**

**대시보드 0~8단계**
- 2~6단계(민간 신호·글로벌 유입·국내 확산·도착 예측·방어 대응)는 운영 API를 부르지 않는 **순수 시뮬레이션** 화면임.
- 0·1·7단계는 일부만 실제 API를 부름.
- 실데이터는 9단계와 `/live`, 새 `/observations`에만 있음.

## ② 흡수 방식: 측정값을 매시간 저장하는 층 하나

```
수집(매시간) ─→ observations 테이블에 측정값·해석값을 시각과 함께 저장 ─→ 화면·경보·상품이 같은 저장본을 읽음
```

- **새 테이블 `observations`**
  - 칸: 층, 대상(ISO3 또는 지역), 측정값(JSON), 해석값(JSON), 출처, 관측 시각.
  - 극지·기후·무역·재난·여행경보를 매시간 1행씩 저장함.
  - 실패한 시각은 '판정 안 함' 행으로 남김. 빈칸을 0으로 채우지 않음.
- **얻는 것**
  - 30일·90일 추이를 볼 수 있음.
  - 과거 재현(백테스트)이 가능해짐. 실측 0건 문제를 과거 데이터로 보완하는 경로임.
  - 판매용 이력 데이터가 생김.
  - 같은 값을 매번 외부 API에 다시 묻지 않아 Comtrade 429 같은 과부하 거절도 줄어듦.
- **비용**
  - 디스크가 조금 늘어남. 예상 1일 수천 행.
  - 백엔드 코드를 바꿔야 하고, 머지하면 Railway가 재배포됨.

## ④ 데이터로 팔 수 있는 것 (후보, 가격은 정하지 않음)

| 상품 | 대상 | 근거 데이터 | 먼저 필요한 것 |
|---|---|---|---|
| 주간 해외유입 위험 보고서(한국어·영어) | 지자체 보건, 병원 감염관리실, 해외진출 기업 | 유입 보고서 + 지구본 + 여행경보 | 지금 바로 무료 베타 가능 |
| 실시간 경보 채널 | 위와 같음 | 텔레그램 경보 + 근거 | 발송 주기 고정(일일 요약) |
| 관측 데이터 API(정규화된 발생 사건 피드 + 출처·측정/추정 표시) | 연구기관, 보험사, 데이터 플랫폼 | `observations` 저장본 | ② 시계열 저장 |
| 선행지표 묶음(극지·기후·무역·재난) | 재보험, 공급망 | 같은 저장본 | ② + 3개월 이상 축적 |
| 공개 성적표(보낸 경보의 적중·오경보) | 모든 고객의 신뢰 근거 | 경보 이력 + 선행성 원장 | 정답 통로 넓히기 |

- 가장 먼저 낼 수 있는 것은 **주간 보고서 무료 베타**임.
- 데이터 API는 ② 시계열 저장이 있어야 상품이 됨.

## ⑤ 지구본: ✅ 1차 완료 (PR #121)

- **레이어**: 발생 보도, 설명 불가 신호, 재난 감시창, 의료물자 급증, 극지 관찰.
- **조작**: 한국 강조, '한국 보기'·'북극 보기', 드래그·버튼 회전, 점 클릭 시 그곳 기록.
- **정직 표시**: 점은 보도·관측이 있었던 곳임. 확진 위치가 아님을 화면에 적었음. 위치를 못 읽은 기록 수도 표시함.
- **다음 할 일**:
  - 점 클릭 시 나라별 페이지(①)로 이동.
  - 시계열이 쌓이면 시간 슬라이더 추가.

## ⑥ 발병국이 어떻게 대처하는가

- **지금은 구조화된 데이터가 없음.** 보도 요약 문장 안에만 들어 있음(예: "WHO가 추가 자료를 요청").
- ▶ **방법**
  - AI 추출 항목에 `대응 조치`를 추가함: 격리, 국경 통제, 백신 접종, 비상사태 선포, WHO 요청 등 정해진 목록에서 고름.
  - WHO 질병발생소식(DON)의 "Public health response" 단락을 따로 읽음.
  - 결과는 나라별 페이지와 지구본 상세에 "확인된 대응 조치(출처·날짜)"로 보여 줌.
  - 출처가 없는 대응은 적지 않음.

## ⑦ 확산을 어떻게 막는가

- 이미 있는 것:
  - 개입 브리핑: 질병별 실측 파라미터가 있을 때만 무대응·약·강 시나리오를 만듦.
  - 재난 감시창: 질병별 잠복 구간.
  - 대응제 격차.
- ▶ 나라별 페이지에 "권장 확인 사항"을 붙임. 근거는 질병별 표준 대응(문헌·WHO 지침) 링크임.
- **모델 숫자는 '예보가 아니라 시나리오' 표시를 유지함.** 우리가 지어낸 처방은 쓰지 않음.

## ⑧ 각 나라 질병청에 알리기: ❓ 캡틴 결정 필요

- **아이기론이 만들 수 있는 것**
  - 나라별 '통보용 브리핑' 문서(PDF·이메일 본문).
  - 담는 내용: 무엇을 언제 어디서 관측했는지, 출처, 측정·추정 구분, 판정 못 한 것.
  - 국제보건규칙(IHR) 보고서와 비슷한 틀로 만듦.
- **자동 발송은 하지 않는 것을 권함**
  - 외국 정부기관에 요청받지 않은 경보를 자동으로 보내면 신뢰와 법적 문제가 생길 수 있음.
  - 오경보 한 건이 기관 신뢰를 잃게 할 수 있음.
- **권장 순서**
  1. 브리핑 생성 버튼(캡틴이 검토 후 직접 발송).
  2. 수신에 동의한 기관만 구독 발송.
  3. 공식 채널은 협약(파일럿)으로 엶. 한국은 질병청 공공AX 쪽을 첫 대상으로 함.

## ⑨ 우리나라

- ▶ 지구본·관측 데이터에서 **한국과 연결된 것**만 모은 "한국 관점" 묶음을 `/korea`에 붙임:
  - 한국행 항공 경로가 있는 발생국
  - 한국의 의료물자 수입 변화
  - 국내 설명 불가 신호
  - 주간 유입 보고서
- ❓ 캡틴이 쓴 "아노적인 것"을 **안보적인 것**(국가 바이오안보 관점)으로 이해했음. 다른 뜻이면 알려 주시길 바람.
  - 안보 관점이면 대응제 격차(국제 비축 없는 병원체)와 고위험 병원체 보도를 함께 넣음.

## ⑩ 극지

- ✅ 지구본에 8곳 표시, '북극 보기' 버튼.
- ▶ ② 시계열 저장 후 지역별 30일 해빙일수·기온 편차 추이를 그림. 남극 반도는 H5N1 야생동물 보도와 함께 보여 줌.

## 권장 순서

1. ② `observations` 시계열 저장(백엔드). 모든 후속 작업의 바닥임. ✅ 구현(2026-11-15, 머지 대기)
   - 매시 경보 주기 뒤 7개 층(극지·기후·토지·삼림·무역·재난·여행경보) 저장. 측정값/해석값 분리.
   - 값이 그대로면 새 행 대신 확인 시각·횟수만 갱신. 못 읽은 시각은 '판정 안 함' 행.
   - `/api/observations/history?layer=&target=&metric=&days=` · `/api/observations/coverage`.
   - 한계: 무역은 품목별 상위 급증 10개국만. 토지·삼림은 키·조회 상태 때문에 지금은 판정 안 함 행만 쌓임.
2. ③ 0~8단계 실데이터 패널. 소스가 이미 있어 웹만 고치면 됨. ✅ 구현(2026-11-15, 머지 대기)
   - 각 단계 위에 '지금 실제로 관측된 것' 표(측정값/해석값 칸 분리, 조회 실패는 '판정 안 함'). 시뮬레이션은 그대로.
   - 0 유전체 계통·bioRxiv(대체 자료는 버림) · 1 설명불가·발생 보도 · 2 SNS 게시량 · 3 CDC 경보·수입 급증·위험지수 ·
     4 이웃 나라 주간 추세 · 5 한국 유입 경로 · 6 재난 감시창 · 7 추출 모델 실적 · 8 대응제 비축 격차.
3. ① 나라별 페이지 + ⑥ 대응 조치 추출 + ⑦ 권장 확인 사항. ◐ 1차 구현(2026-11-16, 머지 대기 · 비용 없는 부분만)
   - `/{ko|en|fr}/observations/{ISO3}`: 관측 강도(추정)·근거·CDC 여행경보·한국 연결, 30일 관측 이력(기후·무역·재난), 받은 관측 종류로 만든 확인 목록(규칙 — 권고가 아님). 지구본 나라 카드에 '나라 페이지 열기' 링크.
   - ⑥ 대응 조치는 AI 추출이 필요해 '아직 추출 안 함(판정 안 함)'으로 표시 — 다음 단계.
4. ⑨ 한국 관점 묶음.
5. ④ 주간 보고서 무료 베타 개시. 1과 병행 가능.
6. ⑧ 통보용 브리핑 생성. 발송 방식은 캡틴 결정 후.

**캡틴 결정 필요 ❓**
- ⑧ 외국·국내 기관 통보 방식: 수동 / 구독 / 협약.
- ⑨ "아노적인 것"의 뜻.
- 위 순서대로 진행할지.
