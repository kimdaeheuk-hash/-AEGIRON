## 오늘 할 일

1. **수집 상태** — `/api/status` 또는 로그의 `📊 소스 건강: 정상 N/3 · …`
   - 소스는 `PolarWatch` · `GenomicVariants` · `Valhalla` 셋. 총계가 3이 아니면 그것부터 적는다.
   - `source_health.collector_silent_hours` 가 2 이상이면 수집기 정지 — 최우선 사고.
   - `long_no_data_sources` · `flaky_sources` · `recent_errors`(같은 에러 반복이면 원문 인용).
2. **시간대별 수집 횟수** — `=== 수집 시작 (극지 · 헤임달 · 발할라) ===` 를 24시간 동안 세어 매시 1회인지 본다. 빠진 시각은 `list-deployments` 와 대조한다.
3. **극지** — `❌ 극지 관찰: 모든 관측지 기상 자료 없음` 이 몇 시에 몇 번인지, 바로 다음 줄 `Open-Meteo 실패 사유` 의 원문(HTTP 429 = 일일 한도). `🗄 관측 저장: 극지 …` 가 매시 찍혔는지.
4. **헤임달** — `Nextstrain SARS-CoV-2` 한 줄(엠폭스·RSV-A 는 개편 2차에서 뺌), `🧬 변이원장` 전이가 있었으면 그 내용.
5. **발할라** — `🛡 매칭원장` 판정, `⚠ 발할라 … (N시간 전 값 사용)` 이 하루 넘게 이어지는지.
6. **외부 감시** — GitHub Actions `Liveness`(빨간불이면 서버 밖에서 본 고장) · `Ledger backup`(어제 03:17 UTC 초록인지).
7. **지난 24시간 커밋** — `git log --since="24 hours ago" --stat`. 수집 경로를 건드렸으면 diff 를 읽고, 파싱(`int()`/인덱싱)·`try` 범위·스케줄러 조건 변경을 본다.

## 보고 형식

- 정상이면 한 문단, 숫자를 넣는다: 소스 n/3, collector_silent_hours, 24시간 수집 횟수, 극지 공백 시간 수.
- 문제가 있으면: 무엇이 / 언제부터 / 왜(근거) — **며칠째인지 계산해서** 적는다.
- 코드는 고치지 않는다. 진단과 보고까지. 원인이 특정되면 고칠 지점(파일:줄)을 적는다.

## 하지 말 것

- 확인 안 한 추측을 결론으로 쓰지 않는다. 로그·`recent_errors` 의 원문을 읽는다.
- 'n개 중 대부분 정상' 같은 뭉뚱그림 금지. 죽은 게 하나라도 있으면 그게 헤드라인이다.
- 소스가 살아 있다고 값이 들어온다고 단정하지 않는다(값 없음과 실패를 가른다).
- 문서에 적힌 숫자를 믿지 않는다 — 로그가 말하는 숫자를 쓴다.
