## 2) ★ 오늘의 발견 — 품질 불변식 줄이 6층 중 3층의 상태를 말하지 않는다 ★

09-18 관측 메모가 *"저하 1 + 정상 1 + 판정불가 1 = 3 이라 6층 중 3층의 상태가 그 줄에
없다. 09-15 에 고친 그 문제가 덜 닫혔을 수 있다. 로그 한 줄로는 단정 못 한다"* 고
열어 뒀다. **오늘 코드에서 확인했다 — 단정할 수 있다. 덜 닫혔다.**

오늘 11·12시 실측:

```
[11:03:26] 🔎 품질 불변식: 정상 정상 2/6 · 판정불가 1
```

2 + 1 = 3. **나머지 3층의 상태가 어디에도 없다.** 그런데 `⚠️ 품질 저하` 가 아니라
`🔎` 정상 갈래다 — 즉 "아무 문제 없다"는 모양으로 3층이 사라졌다.

### 왜 — 셈법이 세 상태만 세고 네 번째를 버린다

`algorithms/quality_health.py:513-516`

```python
"healthy_count":  sum(1 for i in invariants if i["last_result"] == "ok"),
"unknown_count":  sum(1 for i in invariants if i["last_result"] == "unknown"),
degraded = [i for i in invariants if i["alarming"]]   # :508
```

- `healthy_count` = `ok` 인 것만
- `unknown_count` = `unknown` 인 것만
- 줄에 이름이 실리는 것 = `alarming`(연속 위반이 `alarm_after` 문턱을 넘은 것)만

→ **위반했지만 아직 문턱에 못 닿은 층은 셋 중 어디에도 안 들어간다.** 오늘 11시는
Google 차단으로 `local_news` 계열 3개 불변식이 1주기 위반했고, 문턱 미달이라
`healthy` 에서는 빠지면서 이름도 안 실렸다. `quality_report` 의 docstring 이
*"`degraded` 가 비어 있어도 `violating` 은 볼 가치가 있다 — 아직 문턱에 못 미친 저하가
쌓이는 중일 수 있고, 그게 사고가 되기 전의 모습이다"* 라고 **스스로 적어 놓고도**
요약 줄에는 그 숫자를 싣지 않는다.

**이 층의 제1원칙("판정 불가를 정상으로 세지 않는다 — '모른다'와 '괜찮다'는 다르다")이
네 번째 상태에는 적용되지 않았다.** 쌓이는 중인 저하가 정확히 안 보인다.

### 고칠 지점

`algorithms/quality_health.py:551-554` `_healthy_tail()` 에 위반 수를 더한다:

```python
# 현재
return f"정상 {report['healthy_count']}/{report['total_invariants']}{tail}"
# 제안 — 네 숫자의 합이 total 이 되게 한다
#   정상 2/6 · 판정불가 1 · 위반누적 3(문턱미달)
```

`quality_report()` 에 `violating_count`(= `last_result` 가 `ok`·`unknown` 도 아닌 것)를
추가하고 요약 줄에 싣는 것으로 끝난다. 점수·경보·판정은 건드리지 않는다 —
**보이게만 만드는 수정**이다.

### 곁가지 — 같은 줄에 25일 된 오타가 있다

```
🔎 품질 불변식: 정상 정상 6/6     ← '정상' 이 두 번
```

`quality_health.py:548` 이 `f"🔎 품질 불변식: 정상 {_healthy_tail(report)}"` 인데
`_healthy_tail()`(:554)이 이미 `"정상 …"` 을 붙여 돌려준다. #32(09-16)에서
`_healthy_tail` 을 빼낼 때 호출부의 `정상 ` 리터럴을 안 지운 것이다.
저하 갈래(:546-547 `· 나머지 {_healthy_tail(...)}`)는 멀쩡하고 **정상 갈래만** 겹친다.

- 영향: 표시만. 숫자는 맞다.
- **왜 25일간 안 잡혔나**: `tests/test_quality_health.py:176` 의 단언이
  `line.startswith("🔎 품질 불변식: 정상")` 이라 `정상` 이 두 번이어도 통과한다.
  단언이 약해서 못 잡은 자리다 — 고칠 때 이 단언도 같이 조여야 한다.

- **Mobility**: `⏹ 추적 제외됨 — 호출 안 함` 매 주기 정상 출력. (되살림 조건인
  `auth_status` 는 `/api/status` 가 막혀 못 봤다 — 5일 연속.)
- **GroqWatch 은퇴 줄**: 24주기 전부 정상 출력.
- **보정 플래그**: `windows_calibrated=false`·`threshold_calibrated=false` 여전히
  미보정. 잠복 구간은 문헌값, 0.08 은 임의값이다.
- **런칭 관문**: `lead_time` 0건이라 유료 예보 관문은 **정상적으로 닫혀 있다.**

## ★ 못 본 것 — curl 이 다섯 번째 연속 403 이라 /api/status 를 못 읽었다 ★

네트워크는 살아 있다(`api.github.com` → 200). railway.app 호스트가 이 세션의
허용목록에 없어 프록시가 CONNECT 를 거절한다. **장애가 아니라 정책이다.**

```
CONNECT epiweather-api-production.up.railway.app:443 HTTP/1.1
< HTTP/1.1 403 Forbidden
```

로그로 대체 확인한 것은 위에 다 적었다. **로그로는 닿지 않아 끝까지 못 본 것:**

| 못 본 것 | 며칠째 | 왜 중요한가 |
|---|---|---|
| `db_table_counts` | **5일 연속** | 다음 날 비교용 기준값이 닷새째 비어 있다 |
| `retired_sources` (Mobility `auth_status`) | 5일 연속 | 되살릴 수 있는지 판정 불가 |
| `no_data` 소스의 `staleness_hours` | 5일 연속 | 절차 문서가 *"매일 적어두고 늘어나는지 봐라"* 고 시킨 항목 |
| `quality_health.extraction.success_age_hours` | — | 오늘은 로그가 `nvidia_nim_hosted=4` 로 답해줬다(대체 확인됨) |
| 브리핑 `generation_method` | 상시 | `template_fallback` 인지 `llm_polished` 인지 **여전히 모른다** |
| 브리핑 3개 언어 아카이브(ko/en/fr) | 상시 | 직접 확인 못 함 |
| 경보 근거의 Tavily '근사' 고지 줄 | 2일 연속 | 로그에 안 나오는 자리 |

### 브리핑 — 간접 확인뿐이다 (어제와 같다)

22시 UTC 주기 뒤 경보 계산이 **4회 반복**됐다(22:01:45 / 22:01:55 / 22:03:06 /
22:04:05). 수집 주기 1회 + **3회** = 3개 언어 생성으로 읽히지만 **이건 추론이다.**

⚠️ 절차 문서 09-18 절이 이미 적어둔 구조적 문제가 그대로다 —
`daily_brief.py:840` 의 `except Exception: return None` 때문에 LLM 이 죽어도
`template_fallback` 으로 **정상 반환**하고 로그에 한 줄도 안 남는다.
**"브리핑이 성공했다"를 로그로 확인할 방법이 없다.** 승인된 수정안(#32 의
`provider_detail` 로 사유 남기기 + 일곱 번째 품질 불변식)이 아직 미적용이다.

확인법(캡틴이 브라우저로): `/api/daily-brief?lang=ko&format=duo` 의
`generation_method` — 포맷을 명시해야 캐시를 비켜간다(`main.py:1790`).
