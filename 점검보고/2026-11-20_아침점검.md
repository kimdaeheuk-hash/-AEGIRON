## 1. 헤드라인 — 수리 두 개가 들어갔는데 **벽은 1분도 움직이지 않았다**

어제 보고(11-19)가 "판정은 11-19 아침 점검 몫" 이라며 세 갈래 표를 남겼다.
**오늘 관측은 그 표의 세 번째 줄이다.**

### 측정값 — 고장 시각이 이틀 연속 **똑같이 12:00 UTC**

```
11-17  11:00 UTC 부터 끊김   (수리 없음)        · 13주기
11-18  12:00 UTC 부터 끊김   (수리 없음 — #132 는 14:16 배포, 벽보다 2시간 늦다) · 12주기
11-19  12:00 UTC 부터 끊김   (#132 아침 내내 작동 + #134 09:25 배포) · 12주기 · 23:00 까지 진행 중
```

**#132 는 11-18 14:16 UTC 배포라 11-18 의 벽(12:00)에는 아무 영향이 없었다.
11-19 가 호출량을 줄인 채로 맞은 첫 날이고, 벽은 11-18 과 같은 12:00 UTC 다.**
→ 11-17→11-18 의 11시→12시 이동은 수리가 아니라 그냥 날마다의 흔들림이었고,
수리가 들어간 날의 이동폭은 **0** 이다.

### 사유는 어제처럼 서버가 직접 말한다 — 전부 `429`

```
11-19 12:00~16:00 UTC   ⚠ Open-Meteo 실패 사유(극지·기후·오지 합산): HTTP 429×8   (5주기, 극지 8곳만)
11-19 17:00~22:00 UTC   … HTTP 429×23                                  (6주기, 극지 8 + 기후 15)
11-19 23:00 UTC         … HTTP 429×47                                  ← 최신
```

`429×8` 이 다섯 주기 내리 똑같다 = **기후·오지는 그 주기에 아예 안 불렀다**(6시간 캐시 작동).
즉 **#132 의 호출량 감축은 로그로 확인된다. 그런데도 벽이 안 움직였다.**

### ★ 그래서 호출량은 원인이 아니다 — 근거 둘 ★

1. **호출량을 줄인 날과 안 줄인 날의 벽이 같다**(위).
2. **11-19 오전은 호출량이 더 적었다.** #134 가 고친 결함(빈 결과가 6시간 캐시를
   쥐고 앉음) 때문에 `기후 15` 는 00:00~03:00 네 주기 동안 `판정 안 함` 이었다 —
   **그 구간에 기후는 Open-Meteo 를 한 번도 안 불렀다.** 평소보다 적게 부르고도
   같은 12:00 에 벽을 맞았다.

→ 어제 표의 셋째 줄: **한도의 종류부터 다시 봐야 한다.**
   하루 한도를 우리 호출량(어제 추정 하루 250회 남짓)으로 채운다는 설명은
   이 두 관측과 맞지 않는다.

⚠️ **여기서 멈춘다 — 추정을 결론으로 쓰지 않는다.**
분당·시간당 한도일 수도, Railway 송신 IP(sfo)를 남과 나눠 써서 남의 호출에 깎이는
것일 수도 있다. **둘 다 확인된 바 없다.** 샌드박스가 `api.open-meteo.com` 에
못 나가서(허용목록) 응답 헤더를 직접 볼 수 없다.

**확정하는 법(캡틴 결정거리)** — 둘 중 하나:
- `collector.py` 가 429 응답의 **본문/헤더를 한 번만 로그에 남기게** 한다.
  Open-Meteo 는 429 본문에 어떤 한도인지 적어 보낸다. 네트워크 추가 0, 한 줄짜리 수리.
  **이게 가장 값싸고 결정적이다** — 사유 집계 줄 하나가 사흘 진단을 첫 주기에
  끝냈던 것과 같은 자리다.
- 유료 키(`OPEN_METEO_API_KEY`) 를 붙인다. IP 공유가 원인이면 이걸로 끝나고,
  우리 호출량이 원인이면 안 끝난다 — 즉 **이것도 판정 실험이 된다.**

### 영향 — 극지만이 아니다

```
11-19 22:03 UTC  🗄 관측 저장: 극지 8(판정 안 함 8) · 기후 15(판정 안 함 15) · 토지 14(판정 안 함 14) · 삼림 14(판정 안 함 14)
```

하루의 **절반(12주기)** 동안 극지 8곳 + 기후 15개국이 `판정 안 함` 이다.
정직성 장치는 설계대로 작동한다(`판정 안 함`, `없는 행은 내리지 않음`) — **거짓으로
'정상'을 만들지 않는다.** 다만 **반나절은 눈을 감고 있다**는 사실은 그대로다.

⚠️ `토지 14`·`삼림 14` 는 **모든 주기**(한도가 멀쩡한 오전 포함) `판정 안 함` 이다.
→ **한도와 무관한 별건이고, 오늘 자료로는 원인을 모른다.** 추정을 적지 않는다.
   (어제 보고에도 안 적혀 있다 — 다음 점검이 이어서 볼 자리로 남긴다.)

### ★ 절차서가 "며칠 모아라" 한 항목이 모였다 — `매체부족` ★

```
12:00~17:00 UTC  매 주기  병원체 일치 1 · 매체부족 1 ⟨탄저:Periorbital Anthrax Mimicked Necrotizing Infection Following⟩
20:00~23:00 UTC  매 주기  같음
```
**어제는 0건이었고 오늘은 10주기 연속 1건이다.** 전부 같은 한 건(탄저 증례 보고)이고,
매체가 1곳뿐이라 `MIN_PUBLISHERS`(2곳) 문턱에서 걸러졌다.

→ 절차서 지시대로 **캡틴에게 묻는다**: 이 모양(권위 있는 증례 보고 1곳)을 계속 버릴
것인가? **다만 내 관측으로는 아직 '버리는 게 맞다' 쪽이다** — 같은 24시간에
2곳 보도 기준을 넘긴 우간다 탄저가 따로 올라갔고(72.0점), 걸러진 건은 그 사건의
임상 증례 보고다. **문턱을 1로 내리면 오탐이 늘 자리**다. 결정은 캡틴 몫.
